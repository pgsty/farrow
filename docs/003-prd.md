## 1. 执行结论

Piglet 要解决两个相关但体验不同的问题：

1. 零配置快速模式：用户在 macOS 或 Linux 上执行 `piglet up`，无需先写 YAML、安装特权网络 helper，即可得到一台可 SSH、可出网、可配置 CPU/内存/磁盘的本地 Linux VM。
2. Pigsty 实验室模式：用户通过一份声明式配置启动 1～20 台 VM，节点有固定私网 IP、可相互通信、宿主机可按 IP 访问，并能表达 Pigsty 当前 `meta/full/minio/deci/simu/citus/rpm/deb/all` 等环境。

最终架构选择是：**开发一个范围受控的 Go 程序，直接管理 QEMU；借鉴并验证 Lima 的实现经验，但不把 Lima 作为 v1 运行时依赖，也不导入其完整 Go 模块。**

```text
macOS arm64/amd64 ─┐
                    ├─ piglet ─ QEMU ─ HVF/KVM ─ Linux guest
Linux arm64/amd64 ─┘
```

选择这条路径的原因：

- Pigsty 的 VM 模型很小，核心只有镜像、CPU、内存、根盘、数据盘、固定私网 IP、SSH 和生命周期；
- Lima 已经证明 QEMU、cloud-init、SSH、镜像和 `socket_vmnet` 路线可行，但其产品模型是“独立实例 + 文件共享/容器体验”，不是固定地址的多节点实验室；
- 直接封装 `limactl` 仍无法统一满足 Linux bridge 与 macOS `socket_vmnet` 的固定 IP 契约，并引入第二套全局状态、配置合并、guest agent 和版本兼容面；
- 导入 Lima 模块会引入大量与 Piglet 无关的依赖和快速变化的 API；Lima v2.2 本身仍有 driver API breaking change；
- Vagrant 当前源码采用 BUSL-1.1，Piglet 可以学习其 UX 和恢复模式，但不得复制当前 Vagrant 源码进入 Apache-2.0 项目；
- 自己直接驱动 QEMU 的长期维护成本真实存在，因此必须先做纵向 M0 技术验证，并将 Lima 当作行为参考和故障排查资料，而不是盲目重写。

这不是一个通用 Vagrant、Lima 或 libvirt 替代品。v1 只实现 Pigsty 已证实需要的使用面。

## 2. 原 PRD 审查结论

### 2.1 已覆盖的需求

`001-prd.md` 已经较完整地覆盖：

- 原生架构的 QEMU/HVF/KVM；
- qcow2 基础镜像与 COW 根盘；
- cloud-init NoCloud；
- QMP 生命周期；
- SSH、端口转发；
- macOS `socket_vmnet` 与 Linux bridge；
- 多节点并行、部分失败；
- 状态、锁、日志、doctor、debug bundle；
- Pigsty profiles、镜像矩阵、测试和发布。

### 2.2 原 PRD 的关键缺口或错误假设

本版修正以下问题：

1. “零配置单节点”没有真正落地：原流程要求先执行 `piglet init meta`，且无配置时 `up` 报错。
2. private 网络被误建模为每项目任意 CIDR，但 `socket_vmnet` daemon 和 Linux bridge 实际是宿主机全局资源；多个项目复用 `10.10.10.0/24` 会产生 IP/MAC 冲突。
3. 原文只写 macOS `stream` netdev，却没有说明 socket 协议、reconnect、版本与 fallback；初稿又过度收窄为 `socket_vmnet_client + fd=3`。终局设计是：优先 QEMU Unix `stream` + reconnect，回退 Go dial + `ExtraFiles` + `socket,fd=3`，client 仅作诊断；三种 argv 必须在 M0 probe/E2E 后固化。
4. 只做项目锁不足以保护镜像缓存、端口分配、private 网络 lease 等全局资源。
5. 只记录 PID 不足以防 PID reuse；在发送信号前必须校验 QMP identity 和进程身份。
6. QMP socket 放在深层 XDG 路径可能超过 Unix socket path 上限，需要短 runtime 路径。
7. 本地镜像直接作为 backing file 会因移动、修改或含恶意 backing chain 而破坏 VM；应先按 digest 导入托管缓存。
8. “qcow2 是唯一格式”混淆了分发 artifact、导入源和运行时格式；v1 的托管运行时盘统一为 qcow2，但 importer 可以明确拒绝或转换受支持的来源。
9. 根盘扩容、数据盘持久语义、seed 中私钥的保护、SSH known_hosts 隔离没有定义完整。
10. network-config 在 NetworkManager、netplan 和不同 cloud-init 版本上的行为不能只靠通用模板假设，必须进入镜像契约与 guest matrix。
11. 镜像 manifest 的信任根、版本冻结、本地导入、缓存 GC 与并发没有闭环。
12. 配置中的 `gateway` 实际是 private 网上的宿主机地址；private NIC 不应设置默认路由。
13. Linux private 网络的持久化方式、helper 安装所有权和卸载边界没有完成设计。
14. profile 清单与当前 Pigsty `vagrant/spec` 并不完全一致；迁移必须从当前文件生成对照，而不是凭文档枚举。
15. 原验收矩阵把每个 guest、每个平台、每种网络做全排列，成本过高且没有分层。
16. 原提示词用跨 `GOOS` 的 `go test` 作为编译检查；交叉目标应使用 `go build`/`go test -c`，真实测试由对应 OS runner 执行。
17. 迁移只比较 `spec/*.rb` 会漏掉 provider 模板隐式行为：所有普通节点都有 128GiB `/data` 盘，`minio*` 节点有四块 32GiB 数据盘；测试会“字段对齐但行为回归”。

因此，`001-prd.md` 的方向正确，但不能按“Implementation Ready”原样实施。

## 3. 产品目标与非目标

### 3.1 P0 目标

#### G-001：真正的零配置快速模式

在已经安装 QEMU 的宿主机上：

```bash
piglet up
piglet ssh
piglet stop
piglet start
piglet destroy
```

无需 `piglet.yaml`、sudo、Lima、Vagrant、libvirt、VirtualBox 或额外网络组件。

#### G-002：声明式多节点实验室

通过 `piglet.yaml` 描述节点、资源、磁盘和固定地址，并在 macOS/Linux 上得到等价的 guest 语义。

#### G-003：由 Piglet 完整拥有 Pigsty VM 使用面

至少迁移：

- `meta`、`dual`、`trio`、`full`；
- `minio`；
- `deci`、`simu`、`citus`；
- `rpm`、`deb`、`all`；
- 当前实际存在且仍被使用的 `oss`、`pro`。

上述 13 个 embedded profile 是当前产品基线。后续变更直接修改并评审
Piglet 的 YAML/catalog contract，不再从前序 runtime 配置生成，也不保留
兼容、回退或外部仓库解析路径。

#### G-004：镜像自主与可复现

- 自托管 image manifest 和 qcow2；
- 版本与 SHA-256 固定；
- 已创建 VM 不随 manifest 更新漂移；
- 可审计的导入和发布流程。

#### G-005：安全、可恢复、可诊断

- QEMU 不以 root 运行；
- 所有破坏性路径都有边界检查；
- 状态与事务可在 CLI 崩溃或宿主机重启后恢复；
- 错误包含可执行修复建议；
- 不把 mock 当成 KVM/HVF E2E。

### 3.2 P1 目标

- Homebrew、tarball、RPM、DEB 发布；
- JSON 输出和 shell completion；
- legacy Pigsty wrapper；
- 完整 guest smoke matrix；
- state N-1 迁移。

### 3.3 非目标

v1 不实现：

- GUI；
- suspend/resume、内存快照、live migration；
- hotplug；
- GPU/USB/PCI passthrough；
- virtiofs/NFS/SMB 共享目录；
- Windows host；
- Windows/macOS/FreeBSD guest；
- 跨架构 TCG 正式支持；
- 任意 bridge/VLAN/多子网拓扑；
- 同一宿主机并发运行多个固定 IP private lab；
- 多用户或不可信租户隔离；
- 远程 QEMU、云资源或 Terraform provider；
- Vagrantfile/Ruby 解析；
- 通用 provisioner 或内置 Pigsty 安装器；
- 安全运行不可信镜像的强沙箱。

## 4. 方案评估与决策

| 方案 | 初始开发量 | 依赖/安装 | Pigsty 固定 IP 多节点 | 长期控制力 | 结论 |
|---|---:|---:|---:|---:|---|
| A. 直接封装 `limactl` | 低 | Lima + QEMU；private 仍需 helper | macOS 可借 `socket_vmnet`；Linux 契约不统一 | 低 | 不选作 v1 runtime；保留为 M0 对照实验 |
| B. 导入 Lima Go 包 | 中 | Go 依赖树大，语义耦合 hostagent/guestagent | 仍需改网络与集群层 | 中低 | 不选；升级与裁剪成本不划算 |
| C. Fork/裁剪 Lima | 高 | 自维护 fork | 可改到满足 | 中 | 不选；承担上游全部维护面 |
| D. 独立 Go + 直接 QEMU | 中高 | 基础仅 QEMU；private 增加小 helper | 可精确定义 | 高 | **选择** |
| E. Vagrant QEMU provider | 中 | Vagrant/Ruby 仍存在 | 可做 | 低 | 不符合替换 Vagrant 的目标；不选 |
| F. macOS VZ + Linux QEMU | 中 | 平台分裂 | 可做但两套 runtime | 中 | 性能诱人，但违反统一 QEMU 目标；v1 不选 |

### 4.1 如何使用 Lima

允许：

- 阅读其 QEMU argv、firmware、CIDATA、SSH、状态恢复和 `socket_vmnet` 处理；
- 用相同镜像启动 Lima 实例作为故障定位对照；
- 采用 Apache-2.0 兼容的小段算法时保留 NOTICE、来源、commit 和修改说明；
- 直接使用通用、稳定的小型上游库，而不是复制实现。

不允许：

- 在 v1 正常路径调用 `limactl`；
- 把 Lima 的 `$LIMA_HOME` 当 Piglet 状态库；
- 导入整个 `github.com/lima-vm/lima/v2` 只为少量功能；
- 无来源复制大量 Lima 代码；
- 因 Lima 支持某能力就跳过 Piglet 自己的 E2E。

### 4.2 如何使用 Vagrant 经验

可以学习：

- `up/start/stop/destroy/ssh/status` 的用户心智；
- machine state 与实际 provider 状态分离；
- action rollback、并行和 machine index 的经验。

不得复制当前 BUSL-1.1 Vagrant 源码进入 Piglet。若参考旧版本代码，也必须先单独完成许可证与来源审计；默认只参考公开行为和文档。

### 4.3 M0 重新评估门

若以下任一项在 M0 无法稳定通过，不得继续堆叠完整产品：

- Apple Silicon + HVF 的 `u24` 连续 10 次 create/boot/stop/start/destroy；
- Linux AMD64 + KVM 的同等流程；
- macOS `socket_vmnet` 的 host→VM、VM→VM；
- Linux bridge 的 host→VM、VM→VM；
- 同一 CIDATA/network-config 在至少 Ubuntu 24.04、Rocky 9、Debian 13 上工作。

触发后先比较 Lima 的对应行为，记录 ADR，再决定修正、缩小支持面或重新评估 runtime 复用；不得静默降低验收标准。

## 5. 用户模式

### 5.1 Quick：无配置、无特权的单节点模式

当当前目录不存在 `piglet.yaml` 时，`piglet up` 使用内置 resolved spec：

```yaml
version: 1
name: quick
network:
  mode: user
defaults:
  image: u24
  cpus: 2
  memory: 4GiB
  root_disk: 64GiB
ssh:
  user: dba
nodes:
  - name: meta
    control: true
    disks:
      - { name: data, size: 64GiB, mount: /data }
    forwards:
      - { bind: 127.0.0.1, host: 15432, guest: 5432, protocol: tcp }
      - { bind: 127.0.0.1, host: 13000, guest: 3000, protocol: tcp }
      - { bind: 127.0.0.1, host: 18080, guest: 80, protocol: tcp }
      - { bind: 127.0.0.1, host: 18443, guest: 443, protocol: tcp }
```

规则：

- CLI 不自动写出 `piglet.yaml`；resolved spec 写入项目状态；
- 第一次创建可用 `--image`、`--cpus`、`--memory`、`--root-disk`、`--data-disk` 覆盖，`--no-data-disk` 可关闭默认 `/data` 盘；
- 已存在 quick state 时再次传入不同 flag，必须进入 plan/drift 语义，不得忽略；
- user-mode NAT 提供 DHCP、DNS、出网和 SSH host forward；
- 默认只绑定 `127.0.0.1`，不向局域网暴露；
- 不承诺 guest IP 可由宿主机访问；
- quick 默认转发 PostgreSQL、Grafana、HTTP、HTTPS；只在 quick 生效，lab/private 不注入；
- `--no-default-forwards` 可关闭四条业务转发，`--forward` 可追加；
- 端口冲突按 `preferred + n*10000`（`n=0..4`）的确定性有限序列选择并持久化；重启优先复用，重分配必须显著输出；
- 实际端口物化进 resolved spec；`piglet init quick` 导出完整 YAML，之后进入声明式模式；
- loopback 只阻止远程主机访问，不能隔离同一宿主机的其他本地用户；v1 明确是单用户开发机工具。

示例：

```bash
piglet up
piglet up --image el9 --cpus 4 --memory 8GiB --root-disk 100GiB
piglet up --data-disk 128GiB
piglet ssh
piglet exec -- uname -a
```

### 5.2 Lab：声明式实验室模式

当存在 `piglet.yaml` 或指定 `-f` 时，配置是期望状态。单节点也可以使用 private 模式，以兼容当前 Pigsty 的 `10.10.10.10` 访问习惯。

private 模式必须先完成一次宿主机级安装：

```bash
piglet network install
piglet doctor
piglet up -f profiles/full.yaml
```

### 5.3 Private v1 的并发边界

v1 使用一个宿主机全局网络，默认：

```text
name: piglet
cidr: 10.10.10.0/24
host address: 10.10.10.1
macOS DHCP fallback: 10.10.10.2 - 10.10.10.8
static pool: 10.10.10.9 - 10.10.10.254
```

`.9` 必须保留给现有 EL9 build node/部分 VIP；`.2-.4` 也被 Pigsty 用作 guest 内 L2 VIP。Piglet private NIC 始终静态配置、不会请求 DHCP，并关闭 IPv6 RA/link-local，防止 private NIC 注入 DNS/default route。macOS v1 优先使用 host mode；shared 在无冲突替代网段的原生固定 IP 双节点数据面已通过，可作为等价 fallback。任何模式都必须真实出现 host `.1` 与精确 `/24` route；`VMNET_SHARING_SERVICE_BUSY (1009)` 必须报为外部 sharing service/网段冲突，不能把 listening socket 当成功。是否能彻底关闭 DHCP 是优化项，地址正确性不依赖它。

默认网段被 VM/VPN/LAN 或 stale vmnet allocation 占用时，v1 允许一次显式的宿主机全局 RFC1918 IPv4 `/24` override。只接受 canonical `/24`；host 固定为 `.1`、DHCP end 固定为 `.8`、static 为 `.9-.254`。`init PROFILE --network-cidr` 只对 embedded profile 保留尾号重映射；任意用户 YAML 不被静默修改。所有非默认使用必须输出 warning，且 installed network、resolved spec、state、lease 与节点地址必须精确一致。mode/CIDR 变化要求无 active lease 并显式 uninstall→install。

为避免两个项目同时声明相同 IP，v1 **只允许一个 active private project**。同一项目可有多台 VM；其他 private 项目启动时返回明确冲突及当前 lease 信息。user 模式项目不受此限制。

本限制是产品边界，不是多租户安全保证。多个 Unix 用户共享宿主机不属于 v1 支持范围。

## 6. 支持矩阵

### 6.1 Host

| Host | Arch | Accelerator | 等级 | 发布要求 |
|---|---|---|---|---|
| macOS | arm64 | HVF | Tier 1 | 每次 release 真实 E2E |
| Linux | amd64 | KVM | Tier 1 | 每次 release 真实 E2E |
| macOS | amd64 | HVF | Tier 2 | build/golden + 周期性真实 smoke |
| Linux | arm64 | KVM | Tier 2 | build/golden + 周期性真实 smoke |

规则：

- 仅原生 guest arch；非原生请求直接拒绝；
- macOS QEMU 下限为 8.2.1，Linux 下限为 6.2；最终以 capability probe 为准；
- Linux 6.2～8.1 为 best-effort host：probe 通过即可用，但不进入每次发布 E2E；Ubuntu 22.04/EL8 等旧宿主机不得被文案误称为 Tier 1；
- 不因版本号足够就假设 accelerator、machine、device 或 netdev 存在；
- Linux quick 模式不强制某一发行版，但 private installer v1 只承诺 systemd + `iproute2` + 可用 `qemu-bridge-helper` 的宿主机；
- WSL、NetBSD、DragonFlyBSD、Windows host 不支持。

### 6.2 Guest

GA 支持别名：

```text
el9 el10
d12 d13
u22 u24 u26
```

可后续增加：

```text
alma8 alma9 alma10
oracle8 oracle9
```

测试分层：

- 每次 release：`u24` 在两个 Tier 1 host 上完成 quick + private/full E2E；
- 每次 release：`el9`、`d13` 完成 boot/SSH/cloud-init/root grow/data disk smoke；
- 其余正式镜像：按 arch 做周期性或发版候选 smoke；
- image entry 未通过对应 arch 的真实 smoke 前不得标记 `supported`。
- v1.0 GA 前，7 个正式 guest × 两个 Tier 1 原生架构共 14 个 entry 必须各有至少一次可追溯真实 smoke；不要求每次 patch release 重跑全部 14 个。

## 7. 系统架构

```text
                        ┌──────────────────────┐
                        │ CLI / output / UX    │
                        └──────────┬───────────┘
                                   │
                        ┌──────────▼───────────┐
                        │ Config + Resolver    │
                        │ Planner + Diff       │
                        └──────┬───────┬───────┘
                               │       │
                   ┌───────────▼─┐   ┌─▼────────────────┐
                   │ Image Store │   │ State/Locks/Lease│
                   └──────┬──────┘   └─┬────────────────┘
                          │            │
                   ┌──────▼────────────▼──────┐
                   │ Node transaction/runtime │
                   └───┬─────────┬─────────┬──┘
                       │         │         │
                ┌──────▼───┐ ┌───▼────┐ ┌──▼───────────┐
                │ qcow2/ISO│ │ Network│ │ QEMU process │
                └──────────┘ └────────┘ └──┬──────┬────┘
                                           │      │
                                          QMP    SSH/serial
```

### 7.1 组件边界

- Config/Resolver：strict YAML、默认值、profile、CLI override、canonical resolved spec；
- Planner：字段级 diff、可变/需停止/需 recreate 分类，不直接做 I/O；
- Image Store：manifest、下载、digest、导入、cache lock、GC；
- Project/State：项目 ID、schema migration、atomic write、transaction journal；
- Runtime：每节点 prepare/start/stop/recover；
- Network：`user`、Darwin private、Linux private 三个明确实现；
- QEMU：capability、platform profile、argv、process identity、QMP；
- Guest init：CIDATA、SSH、ready marker、disk mount；
- Diagnostics：doctor、events、logs、bundle、JSON output。

```text
profiles/

```

不要为不存在的第二个 hypervisor 建 provider framework。只在确有平台差异处使用小接口。

### 8.3 配置规则

- YAML 是唯一用户编辑格式；未知字段必须报错；
- `version` 必填；
- size、duration、CIDR、IP、MAC 使用强类型解析；
- 默认值解析后形成 resolved spec，state 记录 resolved spec 与 hash；
- Go validation 是语义真相；JSON Schema 从同一类型/约束生成或由测试证明一致，不维护两套易漂移规则；
- YAML 中不得出现 secret 或 private key；
- `storage.data_root` 若设置必须为绝对、安全、可写且不能是 home/workspace/XDG 根本身；只在项目首次创建时生效；
- node name 必须是受限 DNS label；`host_aliases` 可为合法 DNS name/FQDN；两者都在项目内去重；
- `control: true` 最多一个；多节点若未指定则第一节点为 control，并给出 resolved 输出；
- `ssh.user` 是唯一 login user；Quick 与全部官方 profile 均为 `dba`，readiness、ssh、exec、ssh-config 全部使用 resolved 值；
- private 配置的 CIDR/host 必须与已安装全局网络一致；`dhcp_end` 以已安装网络为准，若配置显式给出则必须一致并写入 resolved spec；
- `network preflight` 可独立运行，并默认在 network install 与 private plan/up/start/restart/recreate 的首个 mutation 前运行；覆盖 route/interface/address overlap、installed mismatch、backend readiness、ownership partial/tamper 与 vmnet 1009；
- private static address 必须在 CIDR 内、不能等于 network/broadcast/host address、不能落入 DHCP pool；
- user 模式只允许一个 node；
- v1 port forward 只支持 TCP，默认 bind 为 `127.0.0.1`；
- 显式绑定非 loopback 地址必须在 validate/plan 中显示安全警告；
- CPU ≥ 1，memory ≥ 512MiB；
- root disk 不得小于 base virtual size；
- disk name、IP、MAC、host port、mount path 必须唯一；
- mount 必须为绝对路径且不能覆盖 `/`、`/boot`、`/etc`、`/var/lib/piglet` 等保留路径；
- 配置不接受任意 QEMU argv 逃生口；需要的新硬件能力必须通过设计变更加入类型化字段。

### 9.2 命令语义

`up`：

- 无 YAML 且无现有 quick state：按 quick 默认创建并启动；
- 无 YAML 但已有 quick state：使用 persisted resolved spec；
- quick 已存在时不同 CLI override 形成新的 desired resolved spec，按 plan/drift 处理，不静默忽略；
- VM absent：事务式 prepare + start；
- VM stopped：应用允许的 stopped-only 变更后启动；
- VM running 且无 drift：no-op；
- VM running 且变更需要 restart：默认返回字段 diff，只有 `--restart` 才执行；
- 需要 recreate：返回明确 diff 和 exit code 4，绝不自动 destroy；
- 默认等待 QMP、SSH 和匹配 generation 的 guest ready marker；
- `--no-wait` 只等到 QMP 可连接且 identity 正确。

`start`：

- 只启动已经创建的节点；
- absent 返回明确错误，不隐式创建。

`restart` 只对已存在节点执行 stop → start；若 plan 含 recreate-only 变化则拒绝，不借 restart 隐式重建。

`list` 列出当前用户已登记的所有 Piglet project；当前项目的节点状态使用 `status`。

`stop`：

1. 通过 QMP 发送 `system_powerdown`；
2. 等待 `SHUTDOWN`/进程退出至 guest timeout；
3. 若未退出，通过 QMP `quit`；
4. 再等待；
5. 只有 QMP 不可用且进程身份被验证后才发送 SIGTERM，最后才 SIGKILL；
6. 不删除任何磁盘。

`destroy`：

- 默认交互确认；非 TTY 未给 `--force` 时失败；
- 删除 root overlay、非 persistent 数据盘、seed、NVRAM、runtime artifacts 和节点 state；
- 保留 image cache、配置、项目 key，并在输出中明确提示 key 仍保留；
- `persistent: true` 的数据盘默认保留，只有 `--delete-persistent` 加二次确认才能删除；
- 节点仍运行时必须先安全 stop；不能验证进程身份时拒绝 destroy 并提示 repair。

`recreate`：

- 显式执行 stop → 受保护 destroy → up；
- 默认保留 persistent disk；
- 若新配置与保留盘语义不兼容则拒绝。

`repair`：

- 只处理可证明安全的 stale socket/PID/temp/journal；
- 默认先显示动作；涉及删除时需要确认或 `--force`；
- 不自动删除已有 root/data disk。

`ssh-config --install` 幂等写 `~/.ssh/<name>_config` 与主 config 的 Include，name/IP 双 Host，权限 `0600`；`--remove` 只删带 Piglet marker 的自有内容。默认不修改用户 SSH 配置。

`hosts install|uninstall` 仅适用于 private mode，原子修改 `/etc/hosts` 中带 `# piglet:<project-id>` 的本项目块；需要显式特权，不能碰其他项目或旧 `# pigsty dns` 行。

`project purge-keys` 只在项目无运行/保留节点后删除项目 SSH key，单独确认；普通 destroy 永远不代替它。

### 9.3 输出与 exit code

面向人的默认输出必须包含 node、实际状态、地址、SSH endpoint 和下一步建议。机器输出使用稳定 JSON schema，日志文字写 stderr，数据写 stdout。

| Code | 含义 |
|---:|---|
| 0 | 成功 |
| 1 | 一般运行错误 |
| 2 | 配置/参数错误 |
| 3 | 宿主机依赖或能力不足 |
| 4 | 状态冲突、restart/recreate required |
| 5 | 多节点部分成功 |
| 6 | 锁、global lease 或资源冲突 |
| 7 | 完整性、安全或路径边界检查失败 |

`exec` 必须透传远端进程的 exit code；连接失败使用 Piglet 自己的运行错误码并在 stderr 解释。

## 10. 功能需求

### FR-001：Host 探测与 doctor

检查：

- GOOS/GOARCH 与支持级别；
- QEMU system binary、`qemu-img`、版本和实际路径；
- accelerator、machine、CPU model、virtio block/net、QMP；
- Linux `/dev/kvm` 读写权限；
- macOS HVF 实际 smoke，而不只看 help；
- firmware code/vars 候选路径；
- cache/state/runtime path 权限和可用空间；
- Unix socket 路径长度预算；
- SSH client；
- port 占用；
- private helper、bridge/socket、CIDR 路由/VPN 冲突、lease；
- 当前配置、镜像 arch/firmware 和 host 能力是否匹配。

每项输出 `ok|warn|error`、evidence、修复命令。doctor 是只读命令，不自动 sudo 或改系统。

capability cache 必须包含 QEMU binary path、size/mtime/version；任何一项变化后重新 probe。

### FR-010：镜像 manifest、下载与导入

v1 内置只读 JSON manifest，随 Piglet release 发布；不在运行时静默下载“最新 manifest”。结构示例：

```json
{
  "schema": 1,
  "version": 2026082301,
  "generated_at": "2026-08-23T00:00:00Z",
  "images": {
    "u24": {
      "aliases": ["ubuntu", "ubuntu24", "ubuntu2404"],
      "releases": {
        "20260801.0.0": {
          "amd64": {
            "url": "https://repo.example/u24-amd64.qcow2",
            "sha256": "...",
            "format": "qcow2",
            "virtual_size": "4GiB",
            "source_user": "ubuntu",
            "boot": "bios",
            "status": "supported"
          },
          "arm64": {
            "url": "https://repo.example/u24-arm64.qcow2",
            "sha256": "...",
            "format": "qcow2",
            "virtual_size": "4GiB",
            "source_user": "ubuntu",
            "boot": "uefi",
            "status": "supported"
          }
        }
      }
    }
  }
}
```

`source_user` 只描述原镜像的 bootstrap 入口；正式运行 login user 由 resolved `ssh.user` 决定。`virtual_size` 是下载前预校验提示，下载后的 `qemu-img info` 才是事实。

`piglet image sync` 是唯一远程更新入口，且必须显式执行：

- manifest 含单调 `version` 与 `generated_at`；
- 对 manifest **精确字节**做 minisign-compatible Ed25519 detached signature；
- Piglet 内置至少 active/standby 两把 root public key；未知 key ID 或验签失败即拒绝；
- 本地记录已接受版本；低版本默认拒绝，只有 `--allow-downgrade` 可显式回退并留下事件；
- 支持 HTTPS URL 与离线路径；synced manifest 优先，`image reset-manifest` 回到 embedded baseline；
- sync 只更新目录与 provenance，不改变任何已建 VM backing；过旧 manifest 告警但不因时间本身硬阻塞。

要求：

- alias 解析为不可变的 release + arch + digest；
- 下载使用同目录 `.partial`、独占 cache lock、SHA-256 后 atomic rename；
- interrupted download 不得成为有效 cache entry；
- v1 分发 artifact 为 qcow2 文件；压缩 transport 格式必须另开设计并同时定义 artifact digest 与解压后 digest；
- cache 文件名按 content digest，而非用户 alias；
- base image 必须通过 `qemu-img info --output=json -f qcow2`；
- 托管 base 禁止自身存在 backing file；
- base cache 设为普通用户不可写或在每次首次使用/metadata 变化后复验 digest；
- state 记录实际 digest、virtual size、manifest release；
- manifest 更新不改变已有 node backing；
- `status != supported` 的 image entry 使用时显著告警；
- `image prune` 按 state references 做 GC，默认 dry-run，只有 `--yes` 执行，不删除被任何项目引用的 digest；
- cache lock 与 project lock 分离，锁顺序固定并有 timeout。

本地路径不直接成为 backing。`image import` 必须：

1. canonicalize 路径并拒绝设备、FIFO、socket；
2. 显式指定/探测后验证格式；
3. 拒绝外部 backing/data-file、加密和未知 incompatible feature bits，只接受 plain qcow2（可含普通 compressed clusters）；
4. 计算 digest；
5. 复制或安全转换到托管 cache 的临时文件；
6. 复验后 atomic rename；
7. 记录来源只作审计，不再依赖原路径。

### FR-020：项目、目录和锁

当前工作目录首次创建项目时写：

```text
.piglet/project.json
```

仅含 project UUID、schema 和创建信息，不含 secret；自动提示加入 `.gitignore`。

用户数据根按 `PIGLET_DATA_HOME` → 项目 `storage.data_root` → `$XDG_DATA_HOME/piglet` 的优先级解析；项目创建后变更根目录必须走文档化迁移，不能静默产生第二份 state。doctor 始终显示实际路径。目录结构：

```text
<piglet-data-root>/projects/<project-id>/
  project.json
  resolved.json
  keys/
    id_ed25519
    id_ed25519.pub
    known_hosts
  nodes/<node>/
    state.json
    transaction.json
    root.qcow2
    disks/<name>.qcow2
    seed.iso
    nvram.fd
    qemu.log
    serial.log
    events.jsonl
```

短生命周期资源：

```text
$XDG_RUNTIME_DIR/piglet/<short-project>/<short-node>/
```

若无 `XDG_RUNTIME_DIR`，使用权限为 `0700`、包含 UID 的受控临时根。QMP socket、pidfile 等放这里，并在启动前验证完整路径不超过平台限制。

锁级别：

1. cache/global allocator lock；
2. private network lease lock；
3. project lock；
4. node lock（仅在需要并行节点准备时使用）。

代码必须固定锁顺序，避免死锁。只读 `status` 可使用 shared/短锁，但不得看到半写 state。

所有 state/lease/manifest-derived metadata 写入使用：临时文件 → fsync file → rename → fsync parent directory。schema versioned，升级前备份，v1 至少支持从前一 state schema 迁移。

### FR-030：事务和恢复

节点创建使用持久 transaction journal：

```text
absent -> preparing -> prepared -> starting -> running
running -> stopping -> stopped
stopped -> destroying -> absent
```

journal 记录每个已完成动作和可安全回滚资源。可自动回滚：

- 当前事务创建的 `.partial`；
- 尚未附加/启动的 seed、root overlay、新数据盘；
- 当前启动创建的 stale runtime socket；
- 当前事务取得但未使用的 port reservation。

不得自动回滚：

- 事务前已存在的数据盘；
- 已成功启动的其他节点；
- 无法证明 ownership 的文件；
- 外部网络资源。

真实状态优先级：

1. QMP 可连接且 identity 匹配；
2. 验证过 executable/start-time/argv identity 的进程；
3. state 文件仅作为意图和历史，不能证明 VM 正运行。

不得仅凭 PID 向进程发信号。

### FR-040：磁盘

运行时托管磁盘统一为 qcow2。

根盘创建：

1. 按 digest 取得只读、无 backing 的 base；
2. `qemu-img create -f qcow2 -F qcow2 -b <absolute-base> <temp-overlay>`；
3. 若目标 root size 大于 base virtual size，在 VM 未运行时 resize overlay；
4. `qemu-img info --output=json --backing-chain` 复验格式、绝对 backing、size 与 chain；
5. atomic rename 为 `root.qcow2`；
6. state 记录 base digest 和 chain metadata。

禁止 `-u` unsafe backing mode。禁止对运行中磁盘执行 `qemu-img` 修改。

数据盘：

- 每盘独立 sparse qcow2；
- stable serial 使用 project UUID 为 key、node+disk 为 message 的 HMAC-SHA256 前 96 bit，再按 RFC4648 base32 小写无 padding 编码，恰为 20 字符；state 记录映射并测试唯一性/长度；
- guest 通过 `/dev/disk/by-id/virtio-<serial>` 识别，不依赖 `/dev/vdb` 顺序；
- 首次只在确认没有 filesystem signature 时格式化；
- 格式化后用 filesystem UUID 和 `nofail` 写 `/etc/fstab`，避免盘缺失导致 guest 无法启动；
- 默认 filesystem 由 image contract 决定（优先 XFS 或 ext4），resolved state 记录实际值；
- 已有盘不因 seed/reconcile 重建；
- v1 允许 stopped 状态新增盘；删除盘、缩盘需要显式 recreate/删除动作；
- persistent disk 的删除规则见 `destroy`。

### FR-050：cloud-init NoCloud

Piglet 用成熟纯 Go library 生成 ISO9660；不手写未经验证的 ISO parser/writer，也不依赖 `genisoimage`、`xorriso`、`cloud-localds`。

seed 根目录：

```text
meta-data
user-data
network-config
```

要求：

- volume label 为 `CIDATA`（匹配时不依赖大小写）；
- 文件名精确保留连字符；
- 每个 node 有稳定 instance base ID 和递增 generation；需要重跑 per-instance 配置时才改变 instance-id；
- resolved `ssh.user` 是唯一 login user，Quick 与全部官方 profile 均为 `dba`。官方 cloud-init 配方保留 image bootstrap user，并在 users-groups 前收敛 `admin` GID 88，创建 `dba` UID/GID 88：password locked、`/bin/bash`、passwordless sudo、仅项目 public key；readiness 必须先验证 passwd/group/home ownership；自定义 SSH user 不继承该数值身份；
- user-data 包含 hostname、login user、sudo、项目 public key、节点 hosts、root grow、data disk 安全初始化、time sync、ready marker；
- 只有多节点项目的 control node 才接收项目 private key；quick 单节点不注入横向 key；seed 权限 `0600`，debug bundle 永不收集其内容；
- private key 在 guest 落盘权限 `0600`；
- control guest 的 SSH config 只对项目节点名/private CIDR 使用项目 key 与 `StrictHostKeyChecking=accept-new`，不得全局关闭 host key checking；
- management NIC 按 MAC 使用 DHCP 和默认路由；
- private NIC 按 MAC 使用静态地址，不设置 gateway/default route/DNS，并显式提高/禁止默认路由优先级；
- network-config 版本和 renderer 以 image contract/E2E 为准，不能假设所有发行版行为一致；
- time sync client 必须启用并支持 macOS sleep 后 makestep/catch-up；
- ready marker 为 `/var/lib/piglet/ready.json`，含 project/node/generation/spec hash；
- host 必须验证 marker 与当前 generation 匹配，不能把旧 marker 当成功；
- seed ISO 作为只读设备附加；后续是否 detach 由 M0 验证决定，任何方案都不能导致 reboot 后丢失网络。

cloud-init 的 `instance-id` 决定 first boot。修改 user-data 不等于自动生效；planner 必须明确哪些变更需要新 generation/recreate。

### FR-060：QEMU platform profile 和 firmware

基本 profile：

| Host/Arch | Binary | Machine | Accel | CPU |
|---|---|---|---|---|
| macOS arm64 | `qemu-system-aarch64` | `virt` | `hvf` | capability 验证后的 `host` |
| macOS amd64 | `qemu-system-x86_64` | `q35` | `hvf` | capability 验证后的 `host` |
| Linux amd64 | `qemu-system-x86_64` 或 `qemu-kvm` | `q35` | `kvm` | `host` |
| Linux arm64 | `qemu-system-aarch64` | `virt` | `kvm` | `host` |

启动前 probe：

```text
--version
-accel help
-machine help
-cpu help
-device help
-netdev help
```

firmware 由 image manifest 的 `boot` 与 platform resolver 共同决定：

- arm64 必须 UEFI；
- x86 可为 BIOS 或 UEFI，不把所有 x86 image 硬编码为 BIOS；
- UEFI code 只读；vars/NVRAM 每 VM 独立复制；
- firmware 候选路径可 probe，允许显式 host override，但 resolved path/digest 写 state；
- firmware 变化需要 recreate；
- 找不到匹配 firmware 时在启动前失败。

QEMU 使用 headless、显式 block/net device、serial log、QMP、pidfile 和 VM UUID/name。执行始终传 argv slice；shell-escaped command 仅用于显示。darwin/amd64 的 `host` CPU 不可用时必须有 probe 选出的受测 fallback，并进入 golden/Tier 2 smoke。

### FR-070：QEMU process 与 QMP

必须先在 M0 决定并记录 QEMU detach 策略，满足：CLI 退出后 VM 存活、日志可用、子进程不成 zombie；macOS stream 直连与 Go `ExtraFiles` FD fallback 都能保持正确生命周期。

最小 QMP client 支持：

```text
qmp_capabilities
query-version
query-status
query-name
query-uuid
system_powerdown
quit
```

要求：

- 处理 greeting、异步 event、唯一 request ID、timeout/context；
- 同一连接可在 event 与 response 交错时正确 demux；
- 每次操作使用短连接，node 级互斥串行化 QMP 访问，避免默认单 client socket 被并发 status/stop 争用；
- socket 目录 `0700`，socket 仅当前用户；
- QEMU 使用稳定 name/UUID，status/stop 先通过 QMP 核验；
- 记录 process executable、start time、pid、argv hash；
- QMP 不可用时只有进程 identity 全部匹配才可 signal；
- guest 自行 halt 后正确清理 stale runtime artifacts，不误判为 running；
- 不使用 HMP 文本解析。

### FR-080：SSH

- 每项目独立 Ed25519 key；private `0600`，public `0644`；
- 不默认读取或复制用户 `~/.ssh/id_rsa`；
- private key 只注入多节点项目的 control node，public key 注入全部节点；
- 调用系统 OpenSSH，不自建 SSH 协议栈；
- 每项目独立 `known_hosts`，启用严格 host key 验证；首次通过受控 `accept-new` 或启动期采集，host key 变化必须报错；
- recreate/destroy 时只清除该节点在项目 known_hosts 中的旧条目；
- user/private 两种模式都保留 NAT SSH fallback；
- SSH host port 在全局 allocator lock 下选择并持久化，默认 loopback；
- QEMU bind 失败时在有限次数内重新分配，不能无限重试；
- `ssh` 正确处理 TTY；`exec` 透传 stdin/stdout/stderr、signal 和 exit code；
- `ssh-config` 可输出到 stdout，修改用户 `~/.ssh/config` 必须是单独显式命令，v1 默认不修改。

### FR-090：User 网络

- QEMU user-mode NAT/slirp；
- 单 node；
- DHCP、DNS、默认路由、internet；
- SSH 和显式 TCP hostfwd；
- quick 除 SSH 外有四条已物化的默认 hostfwd；声明式 lab 不隐式添加业务转发；
- 无 sudo、无 daemon、跨平台同语义；
- 默认 bind `127.0.0.1`；
- 不承诺 ICMP 与宿主机直接访问 guest IP；
- VPN/proxy 环境异常应在 doctor/troubleshooting 中说明。

### FR-100：macOS Private 网络

使用 upstream pinned `socket_vmnet`，不使用需要整个 QEMU 以 root 运行的 QEMU built-in vmnet backend。

安装布局示意：

```text
/opt/piglet/libexec/socket_vmnet
/opt/piglet/libexec/socket_vmnet_client  # optional diagnostic only
/Library/LaunchDaemons/io.pgsty.piglet.vmnet.plist
/private/var/run/piglet-vmnet.sock
/private/var/db/piglet/network.json
/var/log/piglet-vmnet/
```

要求：

- `network install` 是唯一特权安装入口；先显示将修改的精确文件和网络；
- 安装 pinned upstream immutable release binary；Piglet 内嵌的每 arch SHA-256 是唯一完整性信任根，不以同一上游 release 的 SHA256SUMS 自证；支持本地 artifact 与可选 GitHub attestation；
- 所有 binary、parent directory、plist、state 均 root-owned，普通用户不可替换；不从 user-writable Homebrew path 以 root 执行；
- hash 验证后再处理 macOS quarantine；是否有 upstream notarization 必须在 M0 记录，不能把去除 quarantine 说成公证；
- daemon 以 root 运行，QEMU 以普通用户运行；
- v1 产品默认使用经原生验证的 host mode；shared mode 在无冲突替代网段上也已通过静态 private host↔VM、VM↔VM 数据面，可作为等价 fallback；private NIC 出网不属于契约；
- 凡所选模式存在 DHCP，`dhcp_end` 固定为 `.8`；能否禁用 DHCP 只是 M0 优化，`.9` 合法性不依赖它；
- `network.json` 记录 mode、CIDR、host address、DHCP end、interface-id/network-identifier UUID；daemon 重启复用 UUID，禁止 isolation；mode/subnet 变化需要 uninstall+install，active lease 阻塞；
- QEMU 优先直接使用 Unix stream：`-netdev stream,...,addr.type=unix,addr.path=<sock>,<probed-reconnect-option>`；QEMU 版本间 `reconnect`/`reconnect-ms` 拼写必须 probe；
- fallback 由 Go dial daemon socket，通过 `ExtraFiles` 传 FD 并用 `-netdev socket,...,fd=3`；`socket_vmnet_client` 不进入运行路径，只用于人工诊断；
- M0 必须验证所选 mode 下宿主机持有配置的 `.1`、精确 `/24` route、daemon kill/restart 后 stream 自动恢复；旧 shared 失败证据保留为受污染历史记录，干净替代网段 shared pass 为当前结论；
- 若 pinned upstream host-mode 能力不足，顺序是 fail closed → upstream PR → 等 upstream release；默认不维护私有 fork；
- 每 VM 使用确定性唯一 MAC；
- `status`、重复 install、uninstall 幂等；
- uninstall 只删除带精确 ownership manifest 的资源，并拒绝在 private lease/VM 活动时执行；
- firewall/bootpd/VPN 问题给出可复制诊断，不擅自修改防火墙；
- user 模式完全不依赖此组件。

### FR-110：Linux Private 网络

默认：

```text
bridge: piglet0
address: 10.10.10.1/24
qemu: -netdev bridge,br=piglet0,helper=<validated-qemu-bridge-helper>
```

要求：

- v1 private installer 只支持 systemd host；
- `network install` 创建 root-owned 配置并确保 bridge 开机存在；
- 若需要持久 helper，发布一个职责极小的 `piglet-net`，安装至 root-only `/opt/piglet/libexec`；不得让 systemd 以 root 执行 user-writable Piglet binary；
- helper 只接受固定 schema 的 root-owned network config，不接受任意 shell/argv；
- 探测 `qemu-bridge-helper` 的路径、owner、mode/capability 和实际 attach smoke；
- Debian/Ubuntu：若 helper 无权工作，安装前记录原 owner/mode 并确认不存在非 Piglet `dpkg-statoverride`，再使用 `dpkg-statoverride --update --add root kvm 4750 <helper>`；uninstall 执行 `--remove` 后显式恢复原状态；禁止使用包升级会丢失的 ad-hoc `setcap`；
- RPM 系只验证/报告发行版默认 helper 权限，不擅自改动；
- `/etc/qemu/bridge.conf` 只增删独立注释 marker 包围的 `allow piglet0` 小块，不依赖 inline comment 解析，也不整文件覆盖；
- NetworkManager 存在时安装/卸载只针对 `piglet0` 的 unmanaged drop-in；
- private bridge 不提供 NAT/DHCP；每个 VM 的 management user NIC 提供默认路由与 internet；
- private NIC 静态地址且无默认路由；
- QEMU 普通用户运行；
- uninstall 验证 ownership manifest、active lease、bridge members，再删除 Piglet 自有资源；
- 不覆盖用户已有同名 bridge；发现时只有 metadata 完全匹配才能 adopt，否则失败；
- deb 系 `4750 root:kvm` 将 attach 权限收敛到已有 KVM 用户；rpm 系若为 `4755`，任何本地用户都可能 attach，该差异写入 threat model；
- 不支持 NetworkManager/networkd 任意集成矩阵；持久机制由 M0/M2 ADR 选择，并在零手工预配置的 Ubuntu 24.04 上完成 install→两 VM→uninstall E2E。

### FR-120：Private lease 与多节点

- private `up` 先取得宿主机全局 lease；
- lease 记录 project UUID、owner UID、CIDR、MAC/IP、节点和可验证 runtime identity；
- lease 更新有全局锁和 atomic write；
- 同 project 重入幂等；其他 project 冲突返回 code 6；
- 所有节点停止后可释放 lease；CLI 崩溃后通过 QMP/process identity 回收 stale lease；
- 节点准备可并行，启动并发默认 4，可配置但受 host resource check；
- 支持节点子集，但依赖/control 语义清晰；
- 全部 guest `/etc/hosts` 一致；
- 部分失败返回 code 5，成功节点默认保留；
- `--rollback` 只能回滚本次创建且可证明安全的节点，不删除事务前资源；
- 不在 private 失败时静默退回 user mode。

### FR-130：Drift、plan 与 reconcile

字段分级：

| 变化 | Running | Stopped | 动作 |
|---|---|---|---|
| CPU、memory | restart required | 可应用 | 重启后生效 |
| 增大 root disk | stop required | 可离线增长 | 不允许缩小 |
| 新增 data disk | stop required | 可创建附加 | 不动已有盘 |
| host forward | restart required | 可应用 | 重新构造 netdev |
| image/base digest | recreate | recreate | 不自动执行 |
| arch/machine/firmware | recreate | recreate | 不自动执行 |
| network mode/private IP/MAC | recreate | recreate | 避免 cloud-init 重入风险 |
| 删除或缩小 data disk | explicit destructive | explicit destructive | 默认拒绝 |

`plan` 必须输出字段级 before/after、分类、是否破坏数据和将执行的外部动作。hash 使用 canonical resolved JSON，不包含日志时间等运行态字段。

### FR-140：日志与诊断

节点保留：

```text
qemu.log
serial.log
events.jsonl
```

日志具备时间、level、project/node、operation ID。默认不记录 secret、private key、完整 seed、Authorization header。

`debug bundle` 默认收集脱敏后的：

- Piglet/QEMU/helper version；
- doctor；
- source config 与 resolved spec（secret-safe）；
- state/transaction；
- shell-escaped QEMU display command；
- capabilities；
- logs；
- host/network/route/lease 状态。

bundle 生成前列出文件；测试必须验证不会包含 private key、seed user-data、密码或 token。

## 11. 数据格式与兼容契约

不同数据使用不同格式，不追求“全部 YAML”：

| 数据 | 格式 | 原因 |
|---|---|---|
| 用户配置/profile | YAML | 人工编辑与 review 友好 |
| JSON Schema | JSON | 编辑器和 CI 生态 |
| resolved spec/state/lease | JSON | 严格、可版本化、易做 canonical hash |
| image manifest | JSON | 机器生成、digest/signing 友好 |
| operation events | JSON Lines | append/read/脱敏方便 |
| cloud-init | YAML + ISO9660 | NoCloud 标准契约 |
| root/data runtime disk | qcow2 | sparse/COW/QEMU 原生 |
| QMP | JSON | QEMU 协议 |

### 11.1 Config schema

- `version: 1` 是配置语义版本，不等于二进制版本；
- minor 二进制升级不得改变 version 1 已有字段含义；
- 新增可选字段必须有确定默认值；
- 删除/重命名字段需新 config version 或显式 migration；
- parser 对未知字段 fail closed；
- canonical resolved JSON 对 map key、unit、duration、IP 做确定性编码。

### 11.2 State schema

- state 和 transaction 各自有 schema version；
- 不允许使用配置文件代替运行 state；
- migration 先写备份、再原子提交；
- 较新 schema 被旧 binary 打开时只读报错，不得降级覆盖；
- 所有 state 都记录创建/最后写入的 Piglet version。

### 11.3 Image contract

正式 guest image 必须：

- 原生 arch 的 qcow2，且无外部 backing；
- 支持 manifest 声明的 BIOS/UEFI；
- 包含并启用 cloud-init NoCloud；
- 包含 OpenSSH server；
- 默认 console 可写 serial；
- 支持 virtio block/network；
- 允许 cloud-init 创建/合并 resolved login user；source default user 只作 bootstrap metadata；
- 支持 root growpart + resize filesystem；
- 清理 machine-id、SSH host keys、cloud-init cache；
- 清理已知公开开发 keypair、遗留 password 和旧 `authorized_keys`；cloud-init 对既有用户的 merge 不能被当成凭据清理；
- network-config 能按 MAC 配 management/private 两张 NIC；
- 至少有 XFS 或 ext4 工具用于数据盘；
- 启用 chrony 或等价 time sync，并能在 host sleep/大时差后 step/catch-up；
- 通过对应 arch 的 Piglet image E2E。

镜像构建不是 Piglet runtime 的职责，但必须在单独文档/流水线定义 provenance、来源许可证、build recipe、SBOM（若可用）、SHA-256 和 E2E 结果。不能只从旧 box artifact 手工提取后直接标为正式镜像。

### 11.4 Profile contract

- profiles 随 binary embed，并在仓库保留可 review 的 YAML；
- `piglet init <profile>` 输出注释简洁、schema-valid 的副本；
- catalog schema 3 与 YAML 是 Piglet 自有事实源，不包含前序路径或外部 source lock；schema 3 还固定唯一 inventory ref、direct/build-subset mode 与显式 unused VM；
- CI 固定 catalog policy、精确 YAML digest、resolved semantic hash、13-profile/85-node 集合、全 `dba` UID/GID88 身份、网络/control/alias 不变量，以及普通节点 128GiB `/data` 与所有 `minio*` 节点的 4×32GiB `/data1..4`；
- custom `/24` 必须由同一 profile/scale 同步生成 mode-0600 Pigsty inventory，分类 host/admin/VIP/service/DNS/NTP/no-proxy 语义，拒绝未知地址、host-set 漂移、VIP 冲突和未托管覆盖；
- 发布 gate 不抓取或解析前序 runtime 仓库；一次性迁移对照只保留在 dated evidence 中；
- `--scale` 只缩放 CPU/memory，不缩放 disk、IP、node count；范围 1～64；
- 为保持当前行为，`deci/simu` profile 默认 `scalable: false`，除非未来单独修改 profile contract；
- `--image` 对同构 profile 覆盖所有节点，对 `rpm/deb/all/oss/pro` 等混合发行版 profile 默认拒绝全局替换，除非显式 `--force-uniform-image`。

## 12. 安全要求

### 12.1 权限边界

1. QEMU 永远以调用用户运行；
2. macOS 只有 root-owned `socket_vmnet` daemon 特权；
3. Linux 只有 bridge 安装/持久 helper 和发行版 `qemu-bridge-helper` 具有所需特权；
4. 不执行 user-writable binary 作为 root；
5. network install/uninstall 先显示计划，验证绝对路径、owner、mode、symlink component；
6. privileged helper 使用固定 schema 和 allowlist，不接受 shell string 或任意 command。

### 12.2 文件与进程安全

- QMP/runtime/key/seed 目录 `0700`；private key/seed `0600`；
- 外部命令全部使用 argv；显示命令单独 escape；
- 禁止目录穿越、symlink escape、TOCTOU 可利用的 destroy；
- destroy 对每个目标做 canonical path、root containment、ownership manifest 和预期 file type 校验；
- 不递归删除 unresolved path、空路径、home、workspace root 或 XDG 根；
- PID signal 前验证 identity；
- 不解析不可信 shell output；QEMU JSON output 有 size/depth limits；
- 下载限制最大 artifact size、redirect policy、timeout，要求 HTTPS（本地测试源除外）；
- remote image 必须 checksum；checksum 与 artifact 不能来自同一未认证临时响应作为唯一信任依据。

### 12.3 Guest 与 secret

- 明确声明 Piglet 不隔离恶意 guest；
- QEMU user forward 默认 loopback；
- loopback 仍允许同一宿主机其他本地用户访问 quick 默认转发，v1 不提供本地多用户隔离；
- control private key 只用于项目内部 lateral SSH；
- debug bundle、日志和 JSON 输出不泄漏 key/seed/token；
- SSH 严格 host key；
- seed 生命周期和残留风险写入 threat model；
- 项目销毁后保留 key 的行为必须显示，提供单独 `project purge-keys` 或等价显式动作，不能随普通 destroy 偷删。

### 12.4 Supply chain 与许可证

- release 提供 checksums；建议签名/attestation 作为 GA gate；
- embedded image manifest 是 release artifact 的一部分；
- socket_vmnet version/hash 固定；
- 引入/复制 Apache-2.0 上游代码保留 LICENSE/NOTICE/commit provenance；
- 不复制当前 BUSL-1.1 或旧 MPL-2.0 Vagrant 代码；默认只参考公开行为/文档，任何例外先做逐文件许可证审计；
- 依赖在 CI 做 license 与 vulnerability scan，结果不等于自动证明安全。

## 13. 非功能需求

### 13.1 性能

在 image 已缓存且 host 资源充足时：

- `status` 单项目 20 node 在 1 秒目标内返回；
- quick VM 从命令到 SSH ready 的目标为 60 秒内，硬性超时默认 180 秒；
- 4 node 并发启动，默认并发 4；
- 创建 node 不复制完整 base image；
- user/slirp 管理网会慢于内核 NAT；Pigsty bootstrap 应优先建立本地 repo，后续节点间大流量走 private NIC；
- 不承诺 macOS VM 是严肃数据库 benchmark；
- 不承诺不同 host 或 QEMU 版本 I/O 完全一致。

### 13.2 可靠性

- QMP connect 默认 timeout 5 秒；
- stop guest timeout 默认 60 秒；
- 每个外部命令、HTTP、QMP、SSH wait 都有 context deadline；
- stop/start 不丢 root/data disk；
- host reboot 后能识别 stopped/crashed/stale；
- 连续 30 次 create/start/stop/destroy 无 QEMU、socket、temp、lease 泄漏；
- 磁盘空间不足在 create/resize/start 前尽可能 fail early；
- 部分失败不污染成功 node，也不把失败 state 标为 running。

### 13.3 可观测性

- 每个 operation 有 ID；
- `--log-level` 支持 error/warn/info/debug；
- JSON output 有 schema 与 golden；
- 外部命令失败记录 binary、exit code、受控 stderr 和 display argv；
- 用户错误、host capability、integrity failure、guest readiness timeout 可区分。

## 14. 测试策略

### 14.1 Unit

- strict YAML、units、CIDR/IP/MAC、reserved mount；
- resolver/default/profile/CLI override；
- canonical spec hash 与 field diff；
- image alias/digest/import/path safety；
- atomic state、migration、lock order、lease；
- transaction rollback；
- deterministic MAC/UUID/serial/port；
- QMP framing、event/response interleave、timeout；
- process identity/PID reuse fixture；
- redaction；
- destroy containment 与 symlink attack。

### 14.2 Golden

四个平台 profile 的 QEMU argv：

```text
darwin/arm64
darwin/amd64
linux/amd64
linux/arm64
```

覆盖 user/private、BIOS/UEFI、single/four disks、seed、forward、firmware override；另含 Linux QEMU 6.2 capability fixture、macOS stream 的 `reconnect`/`reconnect-ms` 两种 probe 结果和 FD fallback。golden 只证明命令生成，不等于 QEMU 可运行。

### 14.3 Integration

- 真实 `qemu-img`：info/create/resize/chain；
- CIDATA 用 Go reader 验证，并在 CI 可选用 `isoinfo` 交叉验证；
- QEMU `-machine none` 或最小 VM QMP handshake；
- fake HTTP 的 partial/checksum/redirect/size/timeouts；
- fake SSH/exit code/TTY；
- crash-injected atomic state 与 journal recovery；
- port bind race；
- manifest 多 key 验签、未知 key、反回滚、显式 downgrade 与离线 sync；
- debug bundle secret canary。

### 14.4 E2E

Tier 1 真实机器：

```text
macOS arm64 + HVF
Linux amd64 + KVM
```

每次 release 至少：

1. `u24` quick：pull/create/root grow/SSH/exec/stop/start/destroy；
2. `u24` private full：host→VM、VM→VM、VM→internet、固定 IP、dual NIC route；
3. `u24` data disk 与 `minio` 四盘；
4. `el9`、`d13` image smoke；
5. recreate/drift；
6. QEMU crash、CLI crash、stale PID/socket/lease；
7. host reboot（或全杀 QEMU + 清 runtime 的等价故障注入）后 status/up 收敛；
8. socket_vmnet daemon kill/restart 后 stream reconnect；
9. quick 默认四条端口映射与冲突重分配；
10. macOS sleep/时间偏移后的 guest clock catch-up；
11. 30-cycle soak；
12. Pigsty bootstrap smoke。

mock、cross-build、Lima 对照均不得标为 E2E pass。缺少另一平台时必须把结果标为 `not run`。macOS arm64 HVF 需要自托管真机 runner；Linux AMD64 KVM 可用具备 `/dev/kvm` 的 runner。

## 15. Pigsty 迁移

### 15.1 一次性迁移与持续 contract

一次性迁移输入、commit 和字段映射保留在 dated evidence，不能重新进入
runtime、catalog schema、测试依赖或发布流水线。持续产品 contract 只有：

- schema 3 catalog 中的 13 个 profile、inventory binding 与 policy；
- 仓内 YAML、精确 digest 与 resolved semantic hash；
- 85 个节点的 name/address/CPU/memory/image/root/data-disk 语义；
- 普通节点 128GiB `/data`，`minio*` 四块 32GiB `/data1..4`；
- `deci/simu` 不响应 scale；所有官方 profile 的 login user 为 UID/GID88 `dba`。

旧 VM 开发环境的附加行为也要迁移或明确删除：

- control node 到其他节点的 SSH；
- private NIC 不抢 default route/DNS；
- `/data` 与 `/data1..4`；
- root grow；
- node/IP SSH config 与 `ssh-config --install`；
- 可选 `hosts install|uninstall`；profile 可用 `host_aliases` 表达 Pigsty 域名，所有修改必须有项目 marker/回滚；
- 统一 login user `dba`，且不继承任何公开开发 key、遗留密码或旧 `authorized_keys`；
- 现有 `pause/resume` 明确不迁移；
- 危险 `nuke` 不做等价全局删除，故障恢复由 scoped `repair`、`destroy`、`network uninstall` 组合完成。

### 15.2 集成方式

Pigsty 只接入一个 VM runtime：

```makefile
PIGSTY_VM ?= pigsty-vm
PIGSTY_INVENTORY ?= $(CURDIR)/.piglet/pigsty.yml
PIGSTY_SSH_CONFIG ?= $(CURDIR)/.piglet/ssh_config
```

Pigsty wrapper 只把受限环境变量翻译成 Piglet typed flags，不提供第二
runtime/provider 分支：

```text
VM_SPEC
VM_IMAGE
VM_SCALE
VM_NETWORK_CIDR（显式全局 RFC1918 `/24`，非默认必须 warning）
VM_ARCH
```

旧 runtime/provider 控制已从 wrapper 删除；wrapper 不读取、不翻译、也不
转发它们。

### 15.3 Piglet 默认路径的发布条件

- Tier 1 quick/private E2E；
- profiles 对照；
- `meta/full/minio/deci/simu/citus` smoke；
- build matrix；
- 自托管 image/manifest；
- 安装/升级/故障排查文档；
- release readiness review 无 P0 blocker。

| 风险 | 缓解 | 必须重开决策的条件 |

## 19. 交叉评审共识、技术验证项与 owner gate

主审与 Claude Code Fable/Max 两轮对抗评审已达成以下共识：

1. v1 使用独立 Go + direct QEMU；
2. Lima 是 reference/test oracle，不是 runtime；
3. 当前 BUSL 与旧 MPL Vagrant 源码都不复制，只参考行为；
4. `piglet up` 无配置就是 quick；
5. quick 使用 user NAT、localhost SSH、默认 `/data` 与四条业务转发，不承诺固定 guest IP；
6. private v1 是一个宿主机全局网络、一个 active project；
7. private 多节点仍使用 dual NIC；
8. macOS 使用 root-owned socket_vmnet daemon，QEMU stream+reconnect 优先、Go FD fallback，client 仅诊断；
9. Linux private v1 只承诺 systemd + 可由 installer 安全赋权/回滚的 bridge-helper host；
10. 用户配置 YAML、state/manifest JSON、runtime disk qcow2；
11. 本地 image 先 import 到 digest cache；manifest 为 embedded baseline + 显式 Ed25519 signed sync；
12. guest matrix 分层，不做无意义的每次全排列；
13. Quick 与全部官方 Pigsty profile 的 login user 均为 UID/GID88 `dba`；必须移除公开开发 key、遗留密码和旧 `authorized_keys`；
14. profile/inventory contract 由 Piglet 自有 YAML、schema-3 catalog、resolved hash、资源与 address-semantic 不变量共同固定，不能漏掉隐式数据盘或 custom subnet 的 Pigsty inventory/VIP/no-proxy 同步；
15. QEMU floor 分平台：macOS 8.2.1、Linux 6.2、probe 终裁；
16. `.9` 保留给现有 build node/VIP，DHCP fallback 到 `.8`；
17. `000` 的 OPEN 项及 `001`、`002` 的实现结论被本文取代。
18. Piglet 作为独立 core/二进制发布；未来 `pig vm` 可以包装调用，v1 不耦合 Pig CLI 发布周期。

尚需在 M0 用证据决定、但不需要产品 owner 先拍板：

- QEMU 最终 detach/daemonize 方式；
- socket_vmnet DHCP disable 可用性；host/shared、全局网段 preflight/override、reconnect 拼写与 FD fallback 已由实现和原生证据固化；
- seed ISO 是否在 ready 后 detach；
- Linux bridge 的具体 systemd 持久实现；
- 每个 image family 的 network-config renderer/template；
- x86 正式 image 的 BIOS/UEFI 明细。

这些是技术验证项。只有其结论改变本 PRD 的用户承诺或非目标时，才回到产品 owner 裁决。

交叉评审已无需要 owner 仲裁的技术分歧。执行前仍有三项资源/组织 gate，实施 agent 不得假定其已具备：

1. 镜像对象存储/域名/带宽，以及 manifest active/standby 私钥保管人与离线签发流程；
2. 可供持续 E2E 的自托管 macOS arm64 HVF runner；
3. production release OIDC/KMS identity、publisher owner、离线恢复与双人发布复核流程。

这些 gate 不阻止 M0 本地技术验证；到对应 milestone 前未满足时必须报告真实 blocker，不能伪造发布基础设施或 E2E。

## 20. Definition of Done

一个 requirement 只有同时满足以下适用项才算完成：

- typed config/API 与明确错误语义；
- unit 或 property test；
- golden/integration；
- 对应平台真实 E2E；
- 文档和 troubleshooting；
- state upgrade/rollback 行为；
- security/path/redaction review；
- 实际依赖 version/commit、许可证与复制来源 provenance；
- 实际运行的命令与结果可追溯；
- 无关键路径 TODO；
- 没有把 error 降成 warning 或把未运行标成通过。
