# ADR-0008: v1 owner scope — Quick baseline and EL8 retirement

- Status: accepted owner decision
- Date: 2026-08-24

## Decision

1. Quick's public baseline is final: login user `dba`, 64 GiB root, and one
   default sparse 64 GiB `/data` disk. ADR-0009 subsequently normalized every
   embedded Pigsty profile to `dba`; their effective 128 GiB ordinary data-disk
   contract remains independent and unchanged.
2. EL8 is removed from the Piglet v1 target and embedded image catalog. The
   formal GA matrix is seven aliases × two Tier-1 native architectures = 14
   entries: `el9`, `el10`, `d12`, `d13`, `u22`, `u24`, and `u26`.
3. The historical EL8 smoke evidence is retained as a negative compatibility
   record, but it is no longer a release gate or user-selectable embedded alias.

## Reason

The active Quick implementation and both Tier-1 product E2Es already prove the
64 GiB + `dba` contract. Root/data size and login identity are separate
dimensions; current acceptance text must describe each explicitly.

Rocky/EL8 arm64's formal 8.10 image uses a fixed 64 KiB kernel granule that the
tested Apple HVF CPU cannot execute. Linux amd64 happened to boot, but carrying
a target that cannot satisfy both Tier-1 native architectures would either keep
GA permanently failed or encourage a forbidden TCG/non-native workaround.
EL9 and EL10 cover the supported Enterprise Linux surface.

## Impact

- Embedded manifest version advances and removes both EL8 artifacts plus the
  `rocky8` convenience alias.
- `image info el8` and `image info rocky8` fail as unsupported instead of
  returning a testing artifact.
- Existing locally cached EL8 bytes are not deleted; they are simply unmanaged
  historical inputs unless a user supplies a separate explicit manifest.
- Historical 8×2 evidence documents remain immutable; readiness evaluates only
  the new 7×2 target.
